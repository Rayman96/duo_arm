# 已知不足

上课前需要知道的限制。每一条都写了对教学的影响；能在课堂上利用的，也写了怎么用。

## 数字孪生和真机的差距

| 不足 | 影响 | 课堂上怎么用 |
|---|---|---|
| 关节限位还是 URDF 里的 ±3.14，没有按真机测量 | 滑块能把关节转到真机到不了的角度 | 第 19 课：让学生对照真机找出实际限位，改 `assets/` 里的 URDF |
| 仿真关节角和真机舵机读数之间的换算（方向、零位）还没对齐 | 仿真里训练的模型不能直接上真机 | 第 25 课系统辨识的素材 |
| 相机用的是针孔模型；真机 2.4 mm 镜头有明显的桶形畸变，视场角也更大 | 仿真画面和真机画面看起来不一样 | 第 26 课：对比 `docs/images/real_*.png` 和仿真画面 |
| 舵机响应（延迟、PD 参数）没用真机数据辨识 | 仿真里的动作比真机更「干脆」 | 第 25 课 |
| 轮子的碰撞体去掉了，底盘是「虚拟关节」驱动的，不模拟轮地摩擦 | 底盘运动是理想的，不会打滑 | 第 4 课可以讲：这就是全向轮的理想运动学 |
| 物体只有桌子和方块 | 杯子、毛巾等需要自己加，毛巾这种软体在 PhysX 里需要另外设置 | 第 7 课的动手内容 |

## 模型训练

| 不足 | 影响 |
|---|---|
| 示范由脚本生成，每条动作都很相似，没有人类示范的多样性 | ACT 在这种数据上特别好学，成功率比真机数据会高 |
| 只有一个任务、一句语言指令 | 体现不出 GR00T 听懂语言、多任务的优势；第 13 课的「现场出新指令」不会成功 |
| GR00T 只做了部分微调（动作头冻结，batch 8），受 32 GB 显存限制 | GR00T 的成绩偏保守；40 GB 以上显存的机器可以做完整微调 |
| 数据集只录了前方和左腕 2 路相机 | 第 23 课的相机消融需要重新生成数据 |
| 每项评估 20 个回合 | 单项差 3–4 个回合不一定说明问题，合起来看才显著（见对比报告） |

## 运行环境

| 不足 | 影响 |
|---|---|
| 只在一台机器上完整验证过（RTX PRO 4500 32 GB、Ubuntu 22.04、Isaac Sim 6.1 容器） | 新机器装好后先跑 `tools/run_checks.sh`；其他显卡上的用时和显存会有差别 |
| 训练好的模型在私有的 Hugging Face 仓库里 | 需要仓库所有者授权；拿不到就按第 06、07 节自己训练 |
| 仿真窗口只能显示在运行它的主机屏幕上，没有做远程推流 | 课堂上用投影仪接主机 |
| GR00T 需要 Hugging Face 账号接受 `nvidia/Cosmos-Reason2-2B` 的许可 | 换账号或换机器要重新登录 |
| 单机器人仿真约 1.4 倍实时，单进程 | 生成大量数据需要 Isaac Lab 多环境并行（还没做） |
